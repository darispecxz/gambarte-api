# WhatsApp document notifications (pilot)
Apply database/migrations/024_pos_whatsapp_dispatch.sql to the cgr database. Feature disabled by default.
Set WHATSAPP_ENABLED=true, WHATSAPP_PROVIDER=evolution, EVOLUTION_API_URL=http://localhost:8080, EVOLUTION_API_INSTANCE="Gambarte Test", EVOLUTION_API_KEY (secret), WHATSAPP_TEST_RECIPIENT (authorized test phone), WHATSAPP_ALLOW_PRODUCTION=false. Clear config cache using the correct PHP binary. Do not use real documents in tests. In production this feature is disabled unless explicitly approved and enabled. The test recipient override redirects documents, so only enable against isolated synthetic data.
The endpoint uses the existing authenticated agency scope, completed POS logs, registered phone and explicit confirmation. Only Bolivia mobile numbers are supported initially. PDFs are generated by existing services; no public files. ACCEPTED means provider accepted, not delivered. UNKNOWN/PROCESSING must be reconciled manually before any resend; no blind retries. One dispatch per agency/type/operation/recipient. No webhooks or background worker yet. National giro PDFs are TODO and recargas do not expose a verified PDF endpoint. Do not use Baileys in production without compliance review.
